# 五子棋 Gomoku

Vue 3 + TypeScript 实现的前端五子棋，15 路标准盘，支持**双人对战**与**人机对战**。

纯前端，零后端依赖，开箱即用。棋理与 AI 独立于框架，可单独单测。

## 特性

- **两种模式** —— 人机对战（玩家执黑先行，电脑执白）与双人对战（同设备轮流落子），切换模式自动重开一局
- **标准 15 路盘** —— 带天元与四星位，木纹底色
- **落子提示** —— 鼠标悬停显示半透明"下一手"幽灵子，颜色跟随当前执子方
- **最后一手标记** —— 红圈标出，连下几十手后不会看丢
- **胜利高亮** —— 制胜五子加金圈并呼吸缩放，比单纯变色更容易一眼看到
- **悔棋** —— 人机模式下一次退到"轮到你"为止，不会白送 AI 一个回合
- **键盘可达** —— 每个交叉点是真实 `<button>`，带中文 `aria-label`（如"第 8 行 第 8 列，黑棋"）
- **响应式布局** —— 窄屏自动改为上下排布，棋盘同时受容器宽度和视口高度约束，不用滚动就能看全

## 设计要点

### 1. 棋理层与框架解耦

`src/game/` 里的代码不 import 任何 Vue API，输入输出都是普通对象。带来两个好处：

- 可以直接在 vitest 的 `node` 环境下跑，不需要 jsdom，测试启动只要几百毫秒
- 换 UI 框架（React / Svelte）时这一层原样复用

Vue 只出现在 `useGomoku.ts` 这一层，负责把引擎状态接进响应式系统。

### 2. 状态不可变，用 shallowRef 而非 ref

每次落子都整体替换 `GameState` 对象，而不是原地修改。因此 `shallowRef` 就足够——

换成深响应式的 `ref`，Vue 会去递归代理 225 个格子和整个历史栈，纯属白费。

### 3. 胜负判定只扫最后一手

朴素做法是每落一子就全盘遍历，`15 × 15 × 4` 个方向。这里只扫描**最后一手所在的四条线**（横、竖、主对角、副对角），并沿正反两个方向各走一遍。

棋局结束时结果完全相同，但每手的开销从"全盘"降到"两条射线"。

### 4. AI 是一层贪心搜索

对每个空点计算两个分数：

- **进攻分** —— 假设我下这里，四条线各自的连子价值之和
- **防守分** —— 假设对手下这里，同样算法

取 `进攻 × 1.05 + 防守` 最高的点。连子价值按长度指数级放大（1 连 = 10，5 连 = 100000），再乘以两端开阔度（两端都空 ×3，一端被堵 ×1，两端全堵 = 0）。

指数分级保证 AI 宁可自己成五，也不会为了堵一个活三而放掉自己的活四；1.05 的攻击权重则避免它一味跟着堵、看不见自己的机会。空盘时直接下天元。

**它不是强 AI** —— 没有博弈搜索、不识别跳子棋型，业余对局够用，但认真下能赢它。换来的是落子瞬时返回，且行为完全确定（没有随机数），测试里可以逐点断言。

## 已知限制

- **未实现禁手规则** —— 采用无禁手规则，黑棋先手优势明显，正式比赛需另加三三禁手、四四禁手、长连禁手判定
- **AI 无前瞻** —— 一层贪心，不会做多步推演
- **无联机对战** —— 双人模式仅限同一台设备

## 代码约定

- ES 模块语法（`import` / `export`），不使用 CommonJS
- 尽可能使用解构导入
- 4 个半角空格缩进，不使用 Tab
- 代码注释使用中文
- 提交信息使用中文
- 完成一系列代码更改后跑 `npm run typecheck`
